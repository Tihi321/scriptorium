## Contract shape decisions (Lead confirmed 2026-10-25)

- `expressions` is omitted (optional in the updated contract; VN Studio defaults to its standard set).
- `scenes[].description` = first narration after `SCENE:` + bible place looks; VN Studio uses it as given and parity
  comparisons ignore the description text.
- Line beats have no display label; `aliasKey` is set when the source spoke under an alias (spelling or alias-key token)
  and omitted for a character's own name.
- `sourceHash` excludes `book.md`: `outline.md`, `bible/bible.md`, `bible/puzzles.md`, `cover-brief.md`, then
  `chapters/*.md` by first number. A `book.md`-only change (cover, title) therefore does not stale the pack; the publish
  hook builds the pack after the publisher's final `book.md` write, so a cover render no longer invalidates it.
- `EVIDENCE:` gets `image {display:"insert", key: vnKey(evidence key), text}`; an `INSERT:` right before it wins, and the
  picture is hidden (`image: null`) at the next beat of its scene, as the legacy importer does.
- `links`/`onFail`/`hints`/`verified` pass through from `bible/puzzles.md` when present. `clueAt` maps a `CLUE:` clue id,
  and a testimony's evidence core ids, to the beat that shows them; `names`/`text` are in the catalog (story's own words
  where a `CLUE:`/`TESTIMONY:` line gives them, canonical text otherwise).

## Behaviour notes

- Scenes are numbered only over scenes with a beat; a cue-only scene is dropped with a warning and its `---` still breaks
  the next scene. A cue with no beat after it in its scene follows VN Studio: an SFX moves onto the last beat if that beat
  has none, other leftover cues are dropped with a warning.
- `ON SCREEN:` is cast only for a bible character or alias. A prop, a page, a crowd or a whole sentence is dropped with a
  warning and is never a synthetic character or a cast beat; a synthetic `speaker_N` exists only for an actual speaker line
  whose label matches no character or alias.
- `SCENE:` is read like VN Studio's legacy `parseSceneLine` (SCP-45 follow-up): split the text at the **first full stop**; the rest
  is the scene description. In the head, the **last comma** starts the time only when that tail is at most 4 words and names a
  known time (English and Croatian, `detectTime`); otherwise the whole head is the place and the time is empty. `placeText` is the
  place phrase only, `time` stays **as written** (`morning`, `midday`, `late afternoon`, `evening`, `ujutro`) and VN Studio
  canonicalises it. The pack `description` = the SCENE rest + the first narration after `SCENE:` (the `background`) + the place
  looks. A `## heading` scene keeps the plain last-comma rule (`placeAndTime`).
- An unknown place keeps `placeKey: null` and its `placeText` (one warning per distinct place); no place is invented, and
  `VN Studio` derives the background from the text, as the legacy importer does. The real soother therefore has all 7 bible
  places and 6 scenes with a null key: "Petra's garden" (×4), "A path through Dragon Land", "Grassy hill with standing
  stones, Dragon Land".
- A stage direction that looks like a speaker label (`SMASH CUT TO: ...`, `FADE TO BLACK: ...`, `INT. ...`) is narration,
  not a character (the real soother has `SMASH CUT TO:`); the list mirrors VN Studio's `DIRECTION_RE`.
- `line.expression` follows the reader: a bracketed word is kept and becomes that speaker's current expression in the scene;
  a line with no bracket inherits the speaker's last expression in that scene, and only a speaker with none yet in the
  scene gets `neutral`. The state resets with the scene (VN Studio's legacy importer does the same; VNO reported the gap:
  e.g. the real soother's Petra keeps `grumpy`, the choice fixture's Mara keeps `worried`).
- A linear book's last written chapter is `isEnding: true` with the outline's ending text (`The End` when it has none); a
  choice book's chapters without choices are endings. The fixtures give their endings explicit text, so the legacy parity
  comparison holds.
- Empty catalog values refuse the write (`VnPackError`): the publish hook logs it and still publishes; `build_vn_pack`
  returns a tool error naming the missing clue/beat. Everything else (unknown speakers/places, dropped ON SCREEN props, key
  collisions, missing beats, puzzle line problems) is a warning.
- `get_vn_pack` recomputes `packHash` and `sourceHash`, compares the catalog's key set with the pack's, and reports
  `stale`/`problems`/`warnings`. `readVnPack` refuses another format/version and a missing catalog.
- The fixtures were generated from the final compiler; the test compares the generated object with the committed JSON and
  the rendered pretty file with the committed bytes, so any compiler change shows up as a fixture diff.
