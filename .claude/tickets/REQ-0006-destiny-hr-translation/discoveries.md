# REQ-0006 discoveries (Book Translator, Phase B)

- 2026-11-09 translator: `release_client_task {}` (as plan B0.5 says) is refused with "give a taskId, or a project and/or role"; only `release_client_task {role: ...}` per role works (src/engine/mcp/server.ts, release_client_task) - suggested: accept an empty call as "release every leased task", or fix the README/plan wording.
- 2026-11-09 translator: `create_project` has no `pauseAfterGlossary`; it is only on `update_project_settings` (src/engine/mcp/server.ts:168 vs create_project ~120-140) - suggested: add it to create_project like the other settings.
- 2026-11-09 translator: there is no MCP way to get a project's own estimate; `analyze_file` estimates with the defaults (gave $0.05 on deepseek for a clientOnly book) - suggested: an `estimate_project {projectId}` tool, or analyze_file with projectId, that uses the project's models.
- 2026-11-09 translator: `get_project` shows `qa.independent: false` before any chunk is scored, although the reviewer is set - suggested: derive it from the settings when nothing is scored yet.
- 2026-11-09 translator: the deterministic glossary check matches the core row "will => volja" against the English future tense "will", giving false minor issues in 6 of 13 chunks - suggested: a per-row option (case/part of speech, or "noun only" note) or skip rows that are common function words.
- 2026-11-09 translator: the glossary stem check misses ordinary Croatian inflection of multiword targets ("Južna mora" vs "Južnim morima", "stoici" vs "stoika") - suggested: compare per word stems for multiword targets.
- 2026-11-09 translator: References titles kept in English (as the brief says) give one glossary issue per entry (20 in book 1) - suggested: skip glossary checks on segments that are mostly a URL/citation, or honour a brief rule.
- 2026-11-10 translator: `pause_translation` drops translator answers that were already accepted (`submit_client_task` -> accepted:true) but whose chunk had not finished the pipeline: 8 accepted translations of book 2 were lost, all 14 chunks back to pending with no `translation` stored - suggested: persist the translator output on accept so a resume skips straight to proofread/QA.
- 2026-11-10 translator: stopping `yarn headless` from a background shell leaves no way to send Ctrl+C on Windows; killing the node process leaves `engine.lock` behind (deleted by hand after checking no process) - suggested: a `engine stop` CLI or an MCP `shutdown` tool that pauses projects and removes the lock.
- 2026-11-10 translator: `edit_chunk` resets the chunk's QA to `{issues: []}` (src/engine/service.ts:348), so a triaged chunk loses its score and `qa.scored` drops (book 1 showed 12/13 after its one triage edit, book 2 12/14 after two); the only way back is `retry_chunk` and answering the whole translate/proofread pipeline again - suggested: keep the old qa with an `edited: true` mark, or re-run only QA on the edited text.
- 2026-11-10 translator: Gemini QA reported a major "Missing inline tags <1> and </1>" on `<1>Regata</1>`, which has them; the fix pass returned the same text and the chunk was flagged (chunk 14, book 2) - suggested: let the deterministic tag check overrule a reviewer "tags" issue when the tags match the source.
- 2026-11-10 translator: the EPUB export keeps `dc:subject` in English ("Literary fiction", "Fate and luck"...) while title and description are translated (OPF of both books) - suggested: translate dc:subject with the metadata, or document that it stays.
